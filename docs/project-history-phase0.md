## 1. 파일 인벤토리 — 대체로 완료

`script00-generate-inventory.py`(최초 07-28, V4까지 개선)가 `data/raw/`를 재귀 스캔해 `metadata/sdot-schema-mapping.xlsx`의 `FileInventory` 시트를 만듭니다.

- 경로/파일명: `relative_path`, `file_name` ✅
- 행수: `row_count` (날짜 컬럼만 부분 로드해서 계산) ✅
- 헤더: `all_columns_list`, `col_count` ✅
- 인코딩: `SUPPORTED_ENCODINGS = ['utf-8','cp949','euc-kr','utf-8-sig']`를 순서대로 시도해 헤더가 실제로 파싱되는 첫 인코딩을 채택 — "헤더 행 기준 판별" 요건과 일치 ✅
- **구분자(delimiter): 기록 안 됨.** `pd.read_csv`를 구분자 지정 없이(콤마 기본값) 호출하고 있어, 실제 파일이 세미콜론/탭 등 다른 구분자를 썼다면 인벤토리 자체가 이를 감지하지 못하고 조용히 잘못 파싱했을 수 있음 — 검증되지 않은 가정

## 2. 스키마 클러스터링 — 요건대로 됐지만 실행 단계에서 흐트러짐

`script00`의 `classify_schema()`는 헤더에 `측정시간`/`등록일자`/`전송시간` 중 무엇이 있는지로 스키마를 나누고, 셋 다 없으면 전체 컬럼 조합의 MD5 해시(`v_unknown_{hash}`)로 분리합니다. **연도가 아니라 헤더 신호 기준**이라는 점에서 가이드라인 요건을 충족합니다.

다만 실제 병합을 수행하는 `script16-merge-yearly-v7.py`의 메인 루프는:
```python
for year in years:
    year_files = df_inv[df_inv['year'] == year]
    ...
    rename_map = rename_dicts.get(version, {})   # version은 schema_version
```
로 **연도를 1차 순회 축**으로 삼고, 그 안에서 스키마별 컬럼 매핑을 적용합니다. 클러스터링 자체는 헤더 기준이지만, 병합 실행 순서는 연도가 우선이라 "연도로 분기하지 않는다"는 원칙이 실행 단계에서는 지켜지지 않습니다. 같은 연도 안에 스키마가 섞여 있어도 처리되긴 하지만, 연도 경계와 스키마 경계가 어긋나는 케이스(예: 연말연시 장비 교체)를 놓칠 위험이 남습니다.

`v2020_2022_corrupted`라는 스키마 버전명 자체가 이미 손상을 인지하고 붙인 이름으로 보이는데, 그 손상의 실체가 무엇인지 코드나 문서에 남아있지 않았습니다 — 아래 3번에서 그 실체를 특정했습니다.

## 3. 시각 손상 확인 — 부분 해결, 핵심 이슈 미해결

| 손상 유형 | 상태 | 근거 |
|---|---|---|
| 지수표기 파괴(E+) | 표면적으로 해결 | `script16` L68-71: 손상된 행을 마지막 컬럼 값으로 치환. 현재 마스터 데이터에 `E+` 잔존 0건 확인. 단, 이 치환값이 진짜 원본인지 검증 로그는 없어 "복구 불가"에 해당하는 값이 조용히 잘못된 값으로 채워졌을 가능성은 배제 못 함 |
| 12시간제 접힘 + 00시 부재 | **미검출·미해결** | 아래 상세 |
| 비표준 구분자(날짜 포맷) | 부분 해결 후 유실 | `.`(점, 리딩 0 없음), `_`(언더스코어+초) 포맷 확인. `script00`은 인벤토리 생성 시 `_`→공백, `.0` 접미사 제거로 부분 정규화하지만, 이 정규화 결과는 인벤토리용일 뿐 실제 병합 파이프라인(`script16`)에는 반영되지 않아 원본 문자열이 그대로 마스터 데이터까지 흘러감 |

**12시간제 접힘 상세 (이번 감사에서 새로 확인)**: 마스터 데이터에 `"HH:MM:SS PM"` 형태(이미 24시간제 hour인데 `PM`이 불필요하게 덧붙음)가 72,079건, 1,096개 센서에 걸쳐 존재합니다. 동일 센서·동일 날짜의 오전 시간대는 `"H:MM"`(초 없음, AM/PM 표기 없음) 형태로 별도 존재해 하루 안에서 두 포맷이 섞입니다. 이 현상이 나타나는 (센서, 날짜) 조합 6,556개 중 **1,100개(16.8%)는 00시 레코드가 통째로 없습니다** — 가이드라인이 명시한 "12시간제 접힘(00시 부재)" 신호와 정확히 일치합니다. `scripts/` 전체에 `AM`/`PM`/`12시간` 처리 코드는 0건입니다(grep 확인).

## 4. 병합 불변식 — 미구현

`script16`의 파일 순회 로직을 코드 레벨로 확인한 결과:
```python
found_files = list(PROJECT_ROOT.rglob(file_name))
if not found_files:
    continue                      # 로그 없음, 카운트 없음
...
except Exception:
    continue                      # 사유 기록 없음
```
- **"수용 + 거부 = 전체" 검증 없음**: 몇 개 파일이 스킵됐는지, 왜 스킵됐는지 지금 코드로는 재구성 불가능. accept/reject 카운터나 `assert`가 전혀 없습니다.
- 파일별 행수 감사: `script00` 인벤토리의 `row_count`가 유일한 기준점이지만, `script16`이 밀림 행 폐기(L79-83) 등으로 실제 몇 행을 버렸는지 파일 단위로 인벤토리와 대조하는 로직은 없습니다.
- 기간 필터: 코드 전체에 연도/날짜 구간으로 행을 자르는 로직 없음 → **금지 사항 위반 없음 (요건 충족)**
- 0 치환: `fillna(0)` 등 사용 이력 없음(grep 0건) → **요건 충족**

## 5. 센서 진단 — 미구현

커버리지, 물리적 범위([-25, 45]°C), 고착 판정, 센서 등급표에 해당하는 코드가 `scripts/` 전체에 없습니다(grep 0건). `script20-check-sensor-location.py`, `script21-mapping-location-v2.py`는 "위치정보 매핑 누락"만 다루며, 측정값 자체의 물리적 타당성 검증은 아직 손대지 않은 영역입니다.
