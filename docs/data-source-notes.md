## 2026-09-07 — KMA API 허브 ASOS 수집 시 발견한 API 제약/결측 표기 이슈

- **1회 요청 상한(중요, 무경고 절단)**: `kma_sfctm3.php`(ASOS 시간자료)는 `tm1`~`tm2`로 31일(744시간)을 초과하는 기간을 요청해도 에러를 반환하지 않고, 요청 구간의 **최신 쪽 31일치만 조용히 잘라서** 돌려준다(예: 1년치를 요청해도 마지막 달만 옴). 실측으로 확인(2020년 1년 요청 → 745행만 반환, 앞부분 11개월 누락). `scripts/script24-collect-kma-asos.py`는 이를 피하기 위해 반드시 달력월 단위(최대 31일)로 청킹하고, 월별 기대행수(일수×24) 대 실제행수를 대조하는 감사를 남기도록 구현함. **향후 AWS 등 다른 KMA API도 동일 계열이면 같은 제약이 있을 수 있으니 새 엔드포인트마다 반드시 먼저 상한을 실측할 것.**
- **결측값 표기의 모호성**: HM(습도)/SS(일조)/SI(일사)는 물리적으로 음수 불가능하므로 `-9`/`-9.0`/`-9.00`을 결측으로 명확히 판정해 NaN 처리함. 반면 **TA(기온)는 한겨울에 실제로 -9.0℃ 근방 값이 나올 수 있어, 원본 텍스트만으로는 결측 sentinel과 실측값을 구분할 수 없음**(KMA 원본 API의 알려진 한계로 보임, 공식 문서에 명시된 구분 규칙을 찾지 못함). 삭제/치환하지 않고 `ta_at_sentinel` 플래그 컬럼만 남겨 판단을 다음 단계로 미룸. 2020-04~2026-08 종로(108) 수집 결과 27건 해당.
- **SS/SI 결측의 대부분은 사실 "야간이라 관측 안 함"**: NaN 처리된 SS/SI 약 45%는 실제 센서 결함이 아니라 야간 시간대(일조/일사가 물리적으로 0인 시간)를 KMA가 값 0.0이 아닌 sentinel(-9)로 표기하기 때문. 원본 raw txt(`data/raw/KMA_ASOS_108/`)는 그대로 보존했으므로, 일사/일조 총량 등을 계산할 때 "야간=0" vs "야간=결측으로 제외"를 구분해서 다시 처리할 수 있음. 지금 단계에서는 결정하지 않고 caveat만 기록.
- **실제 결측 2개월 발견**: 종로(108) 수집 감사 로그(`docs/kma-asos-collection-audit.csv`) 기준 2023-12(744 기대 중 727행, 17시간 결측)와 2024-03(744 기대 중 726행, 18시간 결측)에서 API가 애초에 그만큼만 반환함 — 위 상한 절단 이슈와는 무관(다른 75개월은 정확히 일치했으므로 청킹 로직 문제 아님), 관측소 측 실제 결측으로 판단. 원인 불명, 급한 조치 불필요.
