# 사전등록 (Preregistration)

> 원칙(가이드라인 §9-1): 결과를 보기 전에 모든 임계값·정의를 여기 기록한다. 결과를 본
> 뒤 기준을 바꾸지 않는다. 게이트를 통과 못 하면 있는 그대로 보고한다(억지로 차이를
> 만들지 않는다).
>
> 이 문서는 두 부분으로 구성된다: (1) 연구 설계 단계에서 이미 합의된 Phase 게이트,
> (2) Phase 1 KMA 데이터 수집 과정에서 실측을 통해 새로 확정한 정의/임계값.
> (2)의 항목 중 "제안값"이라고 표시된 것은 이 문서를 쓰는 시점에 처음 제안하는 값이므로
> 연구자 확인이 필요하고, 확인 후 이 표시를 지운다.

## 1. Phase 게이트 (연구 설계 단계에서 합의됨)

| Phase | 내용 | 게이트 |
|---|---|---|
| 0 | S-DoT 감사와 병합 | G0: 연속 24개월 이상 |
| 1 | 참조장(크리깅)과 이상장(ΔT) | G1: LOOCV RMSE 야간≤1.0°C/주간≤1.5°C, G2: 표본≥300대·야간SD≥0.5°C |
| 2 | 이상장의 집계구 일반화 (XGBoost/OLS) | G3: 예측오차 < 야간이상장 공간SD |
| 3 | 노출 회계 (E^A, E^R, Gap) — RQ1 | G4: 순위상관>0.98이면 회귀 |
| 4 | 무더위쉼터 커버리지 감사 — RQ2 | (게이트 없음, 감사 결과 보고) |
| 4b | 재배치 최적화(MCLP, 수요정의 3종 비교) — RQ3 | G5: Jaccard>0.9·교차평가손실<5%면 회귀 |

### 2.2 변수별 가용성 (확정, 결과 해석의 전제로 미리 못박음)

- **일조(SS)·일사(SI)**: ASOS 종로(108) 1개 지점에서만 제공됨. AWS 29개 지점에는
  해당 항목 자체가 없음(KMA AWS 네트워크의 구조적 한계, 버그 아님).
  → **일조/일사는 공간 보간(크리깅)의 대상이 될 수 없다** (지점 1개로는 공간장을
  만들 수 없음). 종로 홀드아웃 지점의 단변량 시계열로만 사용하고, 크리깅 검증
  지표(LOOCV RMSE 등)에는 기온만 사용한다.
- **습도(HM)**: 전체 기간(2020-04~2026-08) 수집 완료 후 재확인한 결과, 2020-04
  표본만 보고 "11개 지점 영구 결측"이라 판단했던 것은 **오판이었음** — 실제로는
  해당 11개 지점에 습도계가 시차를 두고 순차 설치된 것으로 보인다(예: 412는
  2020-10, 417/419는 2021-07, 415/510은 2021-08~09, 401/405/416/509는 2022-09~10,
  403/404는 2023-11~12에 습도 관측 시작). **설치 이후로는 결측률 0~1%로 정상**.
  → 29개 지점 전부 결측 없이 습도를 제공하는 시점은 없고(가장 늦은 403/404가
  2023-12에야 개통), **연도별로 습도 참조장에 쓸 수 있는 지점 수가 다르다**
  (예: 2020년엔 18개 안팎, 2024년 이후엔 29개 전부). Phase 1 습도 크리깅을 할
  경우 연도를 고정된 지점 수로 취급하지 말고, 그 시점에 실제로 결측률이 낮은
  지점만 골라 써야 한다 — 구체적인 "연도별 유효 지점 수" 테이블은 크리깅 코드
  작성 시점에 만든다.

### 2.3 결측값 처리 규칙 (확정)

- **ASOS(kma_sfctm3.php) — HM/SS/SI**: 물리적으로 음수 불가능한 변수이므로
  `-9`/`-9.0`/`-9.00` sentinel을 결측으로 확정 처리(NaN). 근거: 실측 확인
  (`docs/data-source-notes.md` 2026-09-07 항목).
- **ASOS — TA(기온)**: 겨울철 실제 기온이 -9℃ 근방일 수 있어 sentinel(-9.0)과
  실측값이 원본 텍스트상 구분 불가. **삭제/자동 대체하지 않는다.** `ta_at_sentinel`
  플래그 컬럼만 남기고 원본값을 보존한다(2020-04~2026-08 종로 기준 27건 해당).
  - **제안값(확인 필요)**: 이 27건의 최종 처리 방법 후보 — (a) 같은 시각 AWS
    인근 지점(예: 108 자신은 AWS에도 있으므로 제외하고, 가장 가까운 다른 AWS
    지점) 기온과 비교해 -9℃ 근방이면 실측으로 간주, 그 외엔 결측으로 처리, 또는
    (b) 보수적으로 전부 결측 처리. Phase 1 크리깅 코드 작성 시점에 확정하고
    이 절을 갱신한다.
- **AWS(awsh.php) — 전 필드 공통**: `-99` 이하 값을 결측으로 확정 처리(NaN).
  실측 확인 결과 실제 관측값(예: 겨울철 -9~-19℃대 실측 기온)과 sentinel(-99.0)이
  텍스트상 명확히 구분됨(모호성 없음).

## 4. Phase 1 참조장(KED)·이상장 관련 사전등록 — 2026-09-13

- **야간/주간 정의(확정)**: 고정 시간대 — 22:00~05:59(다음날) = 야간, 06:00~21:59 = 주간.
  연구 기간 전체(계절 무관)에 동일하게 적용. 천문학적 일출/일몰이나 ASOS 일조(SS)
  기준이 더 정밀할 수 있으나, 연구 전체의 일관성과 재현성을 위해 고정 시간대를
  채택(연구자 확인, 2026-09-13).
- **참조장 방법**: KED(Kriging with External Drift), 외부 표류 변수는 DEM(SRTM
  30m) 고도. IDW는 비교 대상으로도 쓰지 않음(사용자 지시).
- **참조장 학습 데이터**: AWS 서울 29개 지점(108/종로 포함 — 종로는 ASOS와 같은
  지점이지만 AWS 네트워크의 정식 구성원이므로 참조장 학습에는 포함, ASOS 108은
  별도의 D3 홀드아웃으로 참조장 계산에는 포함하지 않음 — 즉 "AWS의 108"과
  "ASOS의 108"은 물리적으로 같은 위치지만 용도가 다른 별개 데이터로 취급).
- **LOOCV 검증**: AWS 29개 지점에 대해 leave-one-out, 지점별 예측오차를 KST
  22-06시(야간)/06-22시(주간)로 나눠 RMSE 계산 후 게이트 G1과 대조.
- **G4 계열 게이트(재확인)**: G1 LOOCV RMSE 야간≤1.0°C·주간≤1.5°C, G2 표본≥300대
  ·야간ΔT SD≥0.5°C. 결과가 게이트를 통과 못 하면 있는 그대로 보고하고 억지로
  기준에 맞추지 않는다(가이드라인 §9 원칙).

### 4.1 G1 결과 (2026-09-13, script29-build-ked-reference-loocv.py)

- **전체(2024-09~2026-08, 17,481시간×29지점=505,597건, variogram_model='exponential')**:
  야간 RMSE **1.569°C(기준 ≤1.0, 미통과)**, 주간 RMSE 1.413°C(기준 ≤1.5, 통과).
  잔차 테이블: `data/interim/ked_loocv_residuals.parquet`.
- **미통과 원인 진단(500개 야간 시간 표본)**:
  1. variogram 모델 교체는 효과 없음 — exponential 1.588, spherical 1.572(오차범위
     내 유사), gaussian 1.774(악화). 파라미터 튜닝으로 해결될 문제가 아님.
  2. 오차가 29개 지점에 고르지 않고 **소수 지점에 집중** — 412(서대문) RMSE 3.51,
     407(노원) 3.02, 416(은평) 2.88, 419(중구) 2.84, 415(용산) 2.24, 나머지 24개
     지점은 대부분 1.5 이하. 지점 RMSE-고도 상관 r=0.35로 약함(고도만으로 설명
     안 됨) — 특정 지점의 국지적 미기후(도시협곡, 주변 토지피복 등 DEM 고도
     외의 요인)가 원인으로 추정되나 확정하지 않음.
  3. (참고) 결측률이 높았던 411(마포)은 오히려 RMSE 0.51로 가장 낮음 — 결측률과
     LOOCV 오차는 무관.
- **판단**: 빠르게 고칠 수 있는 파라미터 문제가 아니라 구조적 한계로 판단, 전체
  재실행 없이 이 결과를 그대로 채택하고 Phase 1을 계속 진행하기로 함(연구자
  확인, 2026-09-13). G1 야간 미통과는 최종 보고 시 있는 그대로 명시할 것.

### 4.1b ASOS 종로(108) 홀드아웃 검증 (2026-09-21, script36-asos-holdout-validation.py)

가이드라인 §3 "ASOS 종로 홀드아웃(크리깅 미포함)"이 script29에 구현돼 있지 않아 별도
스크립트로 추가함(같은 KED 설정, 같은 17,481시간, 산출: `data/interim/asos_holdout_residuals.parquet`).
기준(G1)은 사전등록 그대로이고 결과를 보고 바꾸지 않음.

- **확인된 사실: AWS 108 관측값 = ASOS 108 실측값.** 두 시계열이 같은 시간 17,459개 중
  17,457개에서 완전히 일치(RMSE 0.001°C). 즉 AWS 108을 학습에 넣으면 ASOS 108은 홀드아웃이
  아니라 **학습 관측 그 자체**가 된다.
- **A(요청 사양): AWS 29개(108 포함)로 적합 → ASOS 108 위치 예측.** 야간 RMSE 0.012°C /
  주간 0.025°C. 크리깅이 관측 지점에서 정확 보간(exact interpolation)하므로 0에 수렴하는 것이
  당연하며 **검증으로서 정보가 없음**(G1 형식상 통과이나 의미 없음).
- **B(독립 홀드아웃): AWS 108을 뺀 28개로 적합 → ASOS 108 실측과 대조.** 108 위치가 어떤
  학습 관측에도 들어가지 않는 실질적 홀드아웃. 결과는 script29 LOOCV의 108 회차 예측과
  **소수점까지 동일**(17,459시간, 최대 차이 0)이므로 새로운 정보는 없고 같은 값을 ASOS로
  재확인한 것.

  | | 야간 RMSE (≤1.0) | 주간 RMSE (≤1.5) | G1 |
  |---|---|---|---|
  | B 전체(ASOS 108, 종로 1개 지점) | **0.726°C** | **0.821°C** | 통과 / 통과 |
  | 봄 | 0.669 | 0.756 | |
  | 여름 | 0.997 | 0.950 | 야간이 기준(1.0)에 근접 |
  | 가을 | 0.607 | 0.795 | |
  | 겨울 | 0.541 | 0.768 | |
  | (참고) AWS LOOCV 29개 지점 전체 | 1.569°C ❌ | 1.413°C ✅ | 야간 미통과 |

- **해석**: 종로 한 지점만 보면 G1을 통과하지만, 전체 29개 지점 LOOCV 야간 미통과(§4.1)의
  원인이 소수 문제 지점(412/407/416/419/415)이라는 기존 진단과 일관됨 — 종로는 문제 지점이
  아니었을 뿐이다. **ASOS 홀드아웃은 §4.1의 G1 판정(야간 미통과)을 바꾸지 않는다.**
- **한계**: ASOS 종로 하나가 유일한 독립 기기가 아니라 AWS 108과 같은 값이므로, 가이드라인이
  의도한 "AWS 네트워크와 독립된 기기로 검증"은 성립하지 않음. 진짜 독립 검증이 필요하다면
  다른 기관/기기 자료가 있어야 함(미확정). 여름 야간 RMSE가 기준에 근접(0.997)한 점은 참고.
- **계절별 RMSE**(가이드라인 "주/야·계절별")도 이 검증에서 처음 산출함(계절은 기상 계절:
  봄 3–5, 여름 6–8, 가을 9–11, 겨울 12–2). 29개 전체 LOOCV의 계절별은 여름이 가장 나쁨

### 4.3b §3 표본 필터 적용 여부 확인 (2026-09-21, script38-check-sample-filter-funnel.py)

가이드라인 §3 표본 기준 "정상 등급 + 커버리지 ≥ 0.5 + ΔT 중앙값 [−10, +10]°C" 중 script31은
'정상 등급'만 적용하고 나머지 두 조건은 이 문서에도 코드에도 없었음. 사후에 기존 산출물로
확인한 결과(상세: `docs/phase1-sample-filter-funnel.md`):

| 단계 | 탈락 | 남음 |
|---|---|---|
| (0) 전체 센서 | — | 1,200 |
| (1) 정상 등급 | 731 | 469 |
| (2) 커버리지 ≥ 0.5 (센서 활동기간 기준) | 0 | 469 |
| (2b) 분석기간 ΔT 산출 있음 | 16 | 453 |
| (3) ΔT 중앙값 [−10,+10]°C | 0 | 453 |
| (4) 위경도 보유 | 0 | 453 |
| (5) 집계구 매핑 | 0 | 453 (집계구 441) |

- **최종 표본에서 필터로 탈락하는 센서는 0대.** ΔT 중앙값은 −0.195~+3.515°C(야간 −0.621~+3.671°C).
  커버리지 ≥ 0.5는 '정상' 등급 정의(≥ 0.8)에 포함되어 자동 충족. 따라서 표본은 달라지지 않음.
- **절차상 유의**: 두 조건은 결과를 본 뒤 사후에 확인한 것이며 이 문서에 사전등록된 적이 없음.
  다만 값이 기준에서 멀어 결과에 따라 기준이 좌우된 경우는 아님.
- **보충(사전등록 정의 아님, 필터로 쓰지 않음)**: 분석기간 기준으로 다시 계산한 커버리지가 0.5 미만인
  센서가 17대(453→436대, 집계구 441→426개). 등급표의 커버리지는 센서 자신의 활동기간 기준이라
  분석기간 안에서의 관측 밀도를 반영하지 못함. 이를 표본 기준에 반영할지는 미결정이며,
  반영하면 G2 야간 SD와 Phase 2 G3 기준값이 달라질 수 있어 재실행이 필요함(이번에는 하지 않음).

## 3. Phase 0 센서 진단(측정값 품질) 정의 — 2026-09-07

Phase 0 체크리스트 5번(센서 진단). `data/processed/master-v2/sdot_master_2020_2026_v2.parquet`
기준. 지금까지는 `measure_time` 등 시간 컬럼만 검증했고 측정값 자체는 검증한 적이
없어 이번에 정의한다. 결과를 보기 전에 아래 기준을 확정하고, 결과를 본 뒤 기준을
바꾸지 않는다.

- **대상 변수**: 기온(`temp_avg`, `temp_max`, `temp_min`). 다른 측정값(습도/미세먼지 등)은
  이번 진단 범위 밖 — 필요해지면 별도로 정의한다.
- **물리적 타당성 범위**: [-25, 45]°C. 위반 = `temp_avg`/`temp_max`/`temp_min` 중 하나라도
  이 범위를 벗어난 유효(non-null)값.
- **커버리지**: 센서별 관측기간 = [해당 센서의 최초 유효 `temp_avg` 관측시각,
  최후 유효 `temp_avg` 관측시각] (스키마상 `temp_avg`를 지원하는 기간, 즉
  `flag_temp_avg==1`인 행만 대상). 기대 관측수 = 관측기간의 총 시간수(시간당 1개
  관측 가정 — 실측으로 중앙값 간격이 60분임을 사전에 확인함, 결과 확인 전 설계
  단계에서 확인한 것이므로 사전등록 위반 아님). 실제 유효값 수 = 관측기간 내
  `temp_avg`가 non-null인 **유니크 시각**(같은 센서·같은 시각 중복 행은 1개로 계산 —
  주간/일간 파일 중복 이슈, §4 참고) 수. 커버리지 = 실제/기대.
- **고착값(stuck value)**: 동일한 `temp_avg` 값이 간격 3시간 이내로 연속 관측되며,
  전체 지속 시간이 72시간(3일) 이상이면 고착 후보로 플래그. 간격이 3시간을 넘으면
  새 구간으로 취급(연속성 끊김).
- **등급 기준**(세 지표 중 가장 나쁜 것을 최종 등급으로 채택 — 정상 < 의심 < 불량):

  | 지표 | 정상 | 의심 | 불량 |
  |---|---|---|---|
  | 커버리지 | ≥80% | 50~80% | <50% |
  | 물리적 타당성 | 위반 0건 | 위반 비율 <1% | 위반 비율 ≥1% |
  | 고착 | 고착 구간 없음 | 최장 3~7일 | 최장 7일 이상 |

- **원칙**: 등급은 정보 제공용 플래그이며, 이 진단만으로 원본 값을 삭제·수정하지 않는다
  (프로젝트 전체 원칙 — flag, don't filter). 등급표는 `docs/sdot-sensor-quality-report.csv`에
  저장하고, 요약은 `docs/data-source-notes.md`에 기록한다.
